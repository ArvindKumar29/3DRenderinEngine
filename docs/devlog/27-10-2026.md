## 1\. Summary \& Architecture Overview

Today’s objective was to establish a clean, scalable, and hermetic build system for the 3D rendering engine. The core goal was to create a workflow where external dependencies, cross-platform build generation, and shader compilation are completely automated, allowing seamless feature development without manual project file manipulation.

### Core Stack \& Tools Configured:

* **Language Standard:** C++20 (`cxx\_std\_20`) for modern language features, strict compiler compliance (`/permissive-`), and standardized data structures.
* **Build System Orchestrator:** CMake (v3.21+) using modern target-based architecture (`add\_library`, `target\_link\_libraries`, `PUBLIC`/`PRIVATE` inheritance).
* **Dependency Manager:** `vcpkg` operating in **Manifest Mode** (`vcpkg.json`).
* **Graphics API \& SDK:** Vulkan SDK (v1.4.363+) with `volk` (meta-loader) and `VulkanMemoryAllocator` (VMA).
* **Shader Pipeline Integration:** Integrated `glslc` (Vulkan SDK) via custom CMake scripts to automate standard GLSL (`.vert`, `.frag`, `.comp`) to SPIR-V (`.spv`) binary compilation.
* **Windowing \& Utilities:** `glfw3` (windowing/input), `glm` (math), `spdlog` (fast logging), and `stb` (image loading).

## 3\. Issues Encountered \& Solutions Applied

During initialization and configuration verification, several build system and environment errors were encountered and resolved:

### Issue 1: Toolchain \& Dummy Path Configuration Failure

* **Error:** `CMake Error: Could not find toolchain file: "C:/path/to/your/vcpkg/scripts/buildsystems/vcpkg.cmake"`
* **Cause:** Hardcoded placeholder path used during initial setup execution.
* **Solution:** Bootstrapped `vcpkg` at a global root directory (`D:\\dev\\vcpkg`), configured system environment variables (`VCPKG\_ROOT`), and mapped the toolchain dynamically via `$env{VCPKG\_ROOT}` in `CMakePresets.json`.

### Issue 2: Strict JSON Parsing Failures

* **Error:** `CMake Error: Could not read presets... Missing '}' or object member name` / `Unexpected character; expected property name`
* **Cause:** Using C-style comments (`//`) inside `CMakePresets.json` and `vcpkg.json` triggered strict syntax validation errors in CMake and vcpkg. Additionally, using capitalized names (e.g., `"RenderingEngine"`) violated vcpkg package naming rules.
* **Solution:** Stripped inline comments from both JSON files and renamed the vcpkg package to lowercase (`"rendering-engine"`).

### Issue 3: Compiler/Generator Mismatch \& Cache Collision

* **Error:** `Generator: Visual Studio 18 2026 does not match the generator used previously: Visual Studio 17 2022`
* **Cause:** Changing the generator string in `CMakePresets.json` while an existing CMake cache (`CMakeCache.txt`) existed in the `build/` directory.
* **Solution:** Cleared the cache by removing the entire `build/` directory (`Remove-Item -Recurse -Force build`) and re-running `cmake --preset default`.

### Issue 4: Vulkan SDK \& Shader Compiler Detection Failure

* **Error:** `Could NOT find Vulkan (missing: Vulkan\_LIBRARY glslc)`
* **Cause:** Missing system environment paths for the local Vulkan SDK installation (`D:\\dev\\3D\_RENDERING\_ENGINE\\VULKAN`).
* **Solution:** Set system environment variable `VULKAN\_SDK` to `D:\\dev\\3D\_RENDERING\_ENGINE\\VULKAN` and added `%VULKAN\_SDK%\\Bin` to the system `Path`. Verified executable discovery using `where.exe glslc`.

### Issue 5: Missing Target Sources in Modular Subdirectory

* **Error:** `CMake Error: No SOURCES given to target: engine`
* **Cause:** `src/engine/CMakeLists.txt` attempted to gather source files using `file(GLOB\_RECURSE ENGINE\_SOURCES ...)` before any `.cpp` or `.h` files were created in `src/engine/`.
* **Solution:** Created initial starter boilerplate files: `src/engine/Engine.h`, `src/engine/Engine.cpp`, and `src/app/main.cpp`.

### Issue 6: Visual Studio Missing Header Error (`spdlog.h`)

* **Error:** `error C1083: Cannot open include file: 'spdlog/spdlog.h': No such file or directory`
* **Cause:** Attempting to build the root solution directly from Visual Studio's default folder view without generating or loading the underlying CMake project target definitions.
* **Solution:** Executed `cmake --preset default` to generate a native Visual Studio Solution (`build/RenderingEngine.sln`), or opened the folder directly via **File -> Open -> Folder** and selected the `VS 2026 + vcpkg` CMake target.
